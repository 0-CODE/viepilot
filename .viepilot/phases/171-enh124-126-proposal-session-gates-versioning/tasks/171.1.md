# Task 171.1 — ENH-124 + ENH-126: Proposal store: layout, versions, provenance, hashes

## Objective
A storage library that never overwrites and records provenance for each version.

## Paths
- `lib/proposal-store.cjs` (new)
- `lib/proposal-generator.cjs`

## Implementation Notes
- `createProposal`, `newVersion(slug)` → `versions/v{n}-{date}/` (n increments even on the same day), `versionPaths(slug, version)` for pptx/docx/md/script*/review/backstage/simulation, `writeProvenance` (viepilotVersion from package.json, skill/workflow versions, generatedAt, gatesPassed[], inputsHash, sha256 per artifact, skillsUsed[]), `readProposal`, `listProposals(projectRoot)`, `detectExisting(projectRoot, {slug, topic})` incl. legacy flat `{slug}-{date}.*`.
- `buildOutputPaths` stays for backward compatibility but is documented as legacy; workflow moves to `versionPaths`.
- `detectHandEdits(slug, version)` compares stored hashes with files on disk.

## Best Practices
- English only in workflows/ and skills/ (enh031 test).
- Tests resilient: `>=` for counts that may grow, no pinned version literals.
- Never touch the real `~/.claude/settings.json` in tests (temp HOME); hook/settings writes are consent-gated with `--dry-run`.
- Follow the ENH-125 tool policy once Phase 170 ships (Read/Grep/Edit/Write/Task/TodoWrite).

- [ ] hand edits detected by hash
