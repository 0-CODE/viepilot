# Task 176.2 — BUG-035: G2 session/store consistency

## Objective
Session, store and provenance agree with each other and never lose a gate.

## Paths
- `lib/proposal-session.cjs`
- `lib/proposal-store.cjs`
- `lib/proposal-gates.cjs`
- `workflows/proposal.md`
- `bin/vp-tools.cjs`

## Implementation Notes
- `setCurrentVersion` also updates `session.currentVersion` (or the session reads it from proposal.json); `vp-tools proposal status` shows both.
- `recordGate(step, kind)` stores `gates[step][kind]`; migrate old `{kind,result,at}` entries; `upgradePlan`/gate lint read the new shape.
- Outline: store as `{slug}-outline.json` (JSON) and keep reading the old `-outline.md` name.
- `scriptDocx`: produce it in the script step via the docx skill path, or drop it from `versionPaths` and the docs — pick produce (workflow already promises it).
- Draft vs sealed: version folder writes allowed (overwrite) while `sealed` is false; `writeProvenance({seal:true})` at Confirm Output seals; after sealing writes fail with a clear "create a new version" error. Simulation runs append under `simulation/` and refresh provenance automatically (`writeRun` calls a provenance refresh hook or the workflow does it).

## Best Practices
- English only in workflows/ and skills/ (enh031 test).
- Tests resilient: `>=` for counts that may grow, no pinned version literals.
- Never touch the real `~/.claude/settings.json` in tests (temp HOME); hook/settings writes are consent-gated with `--dry-run`.
- Follow the ENH-125 tool policy once Phase 170 ships (Read/Grep/Edit/Write/Task/TodoWrite).
- Every new behaviour gets a regression test named after the BUG-035 group (e.g. `phase176-g1-...`).
- Keep existing session/store files readable: any schema change ships with a migration and a test on an old fixture.

- [ ] outline JSON with .json extension; old name still read
