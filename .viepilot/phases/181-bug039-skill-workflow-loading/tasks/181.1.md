# Task 181.1 — BUG-039: Installer: ship each skill's workflow inside the skill + explicit Read step (fix A)

## Objective
Installer: ship each skill's workflow inside the skill + explicit Read step (fix A).

## Paths
- `lib/viepilot-install.cjs`
- `lib/adapters/claude-code.cjs`
- `lib/adapters/index.cjs`
- `skills/*/SKILL.md` (execution_context blocks only, via the renderer — no hand edits beyond vp-proposal)
- `tests/unit/phase181-bug039-skill-workflow.test.js`

## Implementation Notes
- New install step kind `render_skill_workflows` (after copy_dir + rewrite_paths_in_dir) for each selected adapter:
  - for every installed skill, find workflow refs in `<execution_context>` and "Execute workflow from" lines: `@$HOME/{envToolDir}/workflows/X.md`, `@$HOME/.claude/viepilot/workflows/X.md` and bare `workflows/X.md` (vp-proposal).
  - copy `workflows/X.md` into `<skillDir>/references/X.md` (every referenced workflow, e.g. vp-docs gets documentation.md + crystallize.md only if it is in execution_context; request.md mentions outside execution_context are left alone).
  - replace the `<execution_context>` block with:
    ```
    <execution_context>
    **Step 0 (MANDATORY, before anything else):** Read `<absolute skillDir>/references/X.md` with the host's Read tool
    (Claude Code: Read with offset/limit in 400-line chunks for long files). Never read it with Bash (cat/sed/grep/head).
    The hard gates of this skill live in that file.
    </execution_context>
    ```
    and rewrite "Execute workflow from `@...X.md`" to "Execute the workflow in `references/X.md` (loaded in Step 0)".
  - absolute path resolved at install time (no `$HOME`, no `@`); symlink mode (VIEPILOT_SYMLINK_SKILLS) → write the Step 0 path to `<vpDir>/workflows/X.md` instead of copying (skill dir is a link to source).
- Pure function `renderSkillWorkflowRefs(skillMd, {skillDir, workflowsDir, mode})` → {text, refs[]} exported for tests; idempotent (re-running on a rendered file changes nothing).
- dry-run plan lists the new step; `formatPlanLines` shows "skill workflows: N refs".
- Other adapters: same renderer (paths from adapter.skillsDir); note in SPEC if an adapter format cannot hold references/.

## Best Practices
- English only in workflows/, skills/, templates/ (enh031 test).
- Tests resilient: `>=` for counts that may grow, no pinned version literals.
- Tests never touch the real HOME: install into a temp HOME (`VIEPILOT_HOME`/`HOME` override) and inspect the result.
- Follow the ENH-125 tool policy (Read/Grep/Edit/Write/Task/TodoWrite); the bypass-permissions harness may prefer Bash — say so in the report.
- Run `node bin/vp-tools.cjs policy sync --check` after SKILL.md edits (edit outside the policy markers).

## Acceptance Criteria
- [ ] after install into a temp HOME, no installed SKILL.md contains `@$HOME` or `{envToolDir}` or a bare `workflows/` execution_context
- [ ] each skill with a workflow has references/<wf>.md identical to the source workflow and a Step 0 Read line with the resolved absolute path
- [ ] renderer is idempotent and unit-tested on the three ref forms
- [ ] symlink mode handled
