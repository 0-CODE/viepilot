# Task 167.2 — ENH-117c: Persona subagent prompt + feedback synthesis + review report

## Objective
Define what each persona subagent receives and returns, and how the orchestrator turns many opinions
into Keep / Improve / Reject decisions with reasons.

## Paths
- `templates/proposal/persona-review-prompt.md` (new)
- `lib/proposal-review.cjs`

## Implementation Notes
`persona-review-prompt.md` — placeholders `{persona_card}`, `{rubric}`, `{voice_level}`,
`{manifest_json}`, `{script_md}`, `{lang}`. Instructions: stay in character; review independently
(no other persona's output is provided); score every criterion 1–5 with `slide` + `quote` evidence;
list `keep` (what works, must quote), `improve` (problem + concrete rewrite suggestion), `blockers`;
restate the key message in one sentence (feeds C1). Output strict JSON:
`{ personaId, scores: {H1..C8}, evidence: {H1: [{slide, quote, note}]...}, keep: [...],
improve: [{slide, problem, suggestion, criterion}], blockers: [...], keyMessage }`.

`lib/proposal-review.cjs` add:
- `parseReview(json)` → validates shape; drops scores without evidence (counts as missing, logged).
- `synthesizeFeedback(reviews, { primaryPersonaIds })` → `{ keep, improve, reject }`:
  - Keep = strengths quoted by ≥ 2 personas.
  - Improve = issues with evidence; weight ×2 for primary-audience personas; group by slide.
  - Reject = suggestions that conflict with the chosen voice level or come from a lone non-primary
    persona against a primary-persona Keep; each with a `reason`.
  - Persona #20 has veto on humanity: its H1/H2 improve items are never rejected.
- `buildReviewReport({ rounds, decisions, gate })` → markdown: score table persona × criterion per
  round, Keep/Improve/Reject with reasons, remaining open issues.

## Acceptance Criteria
- [ ] prompt template contains all placeholders and the JSON schema
- [ ] `parseReview` discards a score lacking evidence
- [ ] `synthesizeFeedback` never rejects an item from persona 20 on H1/H2
- [ ] conflicting suggestion from a lone non-primary persona lands in `reject` with a reason
- [ ] `buildReviewReport` output includes a per-round score table and the three decision lists
