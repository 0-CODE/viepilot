# Task 166.2 — ENH-117b: Manifest animation schema + mandatory Animation step

## Objective
Make animation a required, non-skippable step in the proposal workflow.

## Paths
- `workflows/proposal.md`

## Implementation Notes
- Manifest root: `animation: { transition: "fade|push|wipe" }` — one transition style per deck.
- Per slide: `builds: "auto" | [ ... ]`; cover and closing have their own simple build (title, then
  subtitle/CTA).
- Rule: the number of `[click]` cues in a slide's `speakerNotes` equals its build count; the
  manifest step must generate them together.
- Fill the Animation hook placeholder from 165.2: after pptx write → `applyAnimations(pptxPath, plan)`
  → `validatePptxAnimations`. If any slide lacks a transition or a content slide has 0 builds →
  **stop with an error** naming the slides (no silent skip, mirroring ENH-044 enforcement wording).
- Confirm banner shows `Animation: ✓ {N} slides, {M} builds`.

## Acceptance Criteria
- [ ] workflow has an "Animation (MANDATORY)" step after pptx generation
- [ ] documents `applyAnimations` + `validatePptxAnimations` and the fail-loud rule
- [ ] documents `[click]` count == build count rule
- [ ] manifest schema shows `animation` and per-slide `builds`
