# Task 166.1 — ENH-117b: lib/pptx-animate.cjs — inject transitions and builds

## Objective
Post-process a pptxgenjs-generated .pptx so every slide has a transition and content slides have
click-by-click entrance builds.

## Paths
- `lib/pptx-animate.cjs` (new)
- `package.json`

## Implementation Notes
- Add `"jszip": "^3.10.1"` to `dependencies` (already present transitively; make it explicit).
- `ANIMATION_PRESETS` — restrained set only:
  transitions `fade` | `push` | `wipe` (duration ≤ 500 ms); builds `appear` | `fade` (≤ 500 ms).
  No fly/spin/bounce.
- `async applyAnimations(input, plan)` — `input` = file path or Buffer; `plan` =
  `{ transition: 'fade', slides: [{ index, builds: [shapeOrder...] | 'auto' }] }`.
  For each `ppt/slides/slideN.xml`:
  - insert `<p:transition spd="med"><p:fade/></p:transition>` (or preset) after `</p:clrMapOvr>` /
    before `<p:timing>` per OOXML order; never duplicate if present.
  - for builds: read `p:cNvPr id` of content shapes (skip title placeholder and background), emit a
    `<p:timing>` tree (`p:tnLst > p:par > p:cTn nodeType="tmRoot" > p:childTnLst > p:seq …`) with one
    click group per build, `presetClass="entr"` (fade = presetID 10, appear = presetID 1).
  - `'auto'` = one build per body text shape in order.
  Returns Buffer; when `input` is a path, also overwrites the file.
- `async validatePptxAnimations(input)` → `{ ok, slides: [{ index, hasTransition, buildCount }] }`.
- Pure Node + jszip; well-formed XML (string assembly with escaping; no new XML dependency).

## Acceptance Criteria
- [ ] module `require()`s cleanly; exports `ANIMATION_PRESETS`, `applyAnimations`, `validatePptxAnimations`
- [ ] after `applyAnimations`, every slide XML contains exactly one `<p:transition`
- [ ] slides with builds contain `<p:timing>` with ≥ 1 click group referencing existing shape ids
- [ ] running `applyAnimations` twice does not duplicate transitions/timing (idempotent)
- [ ] `jszip` listed in `dependencies`
