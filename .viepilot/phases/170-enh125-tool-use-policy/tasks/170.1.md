# Task 170.1 — ENH-125: Policy source + classifier

## Objective
Single source of the tool policy with per-adapter mapping, and a pure classifier for Bash commands.

## Paths
- `templates/tool-policy.md` (new)
- `lib/tool-policy.cjs` (new)

## Implementation Notes
- `templates/tool-policy.md`: rules, required tool set (Read, Grep/Glob, Edit, Write, Task, TodoWrite or TaskCreate/TaskUpdate/TaskList), exceptions (vp-tools/lib generators, doc-sync-agent for ≥5 identical edits, adapters without a tool), mapping table for claude-code, cursor-agent, codex, copilot, antigravity (copy the table from ENH-125; Copilot/Cursor/Antigravity have no callable subagent; todo tools from `getTodoCapability`).
- `lib/tool-policy.cjs`: `POLICY_VERSION`, `TOOL_MAP` (frozen, keyed by adapter id from lib/adapter-context.cjs), `renderPolicyBlock(adapterId)` → markdown `<tool_policy>` block, `classifyBashCommand(cmd)` → `{ violation: bool, kind: "edit"|"read"|"search"|null, suggestion }` for sed -i, perl -pi, awk/cut/tr > file, python/node writing files (open(..., "w"), writeFileSync), heredoc/`>`/`>>`/tee into paths, cat/head/tail/sed -n/less on files, grep/rg/find for search; allow-list: git, npm/npx/node running scripts/tests, vp-tools, ls, mkdir, the document-skill scripts.

## Best Practices
- English only in workflows/ and skills/ (enh031 test).
- Tests resilient: `>=` for counts that may grow, no pinned version literals.
- Never touch the real `~/.claude/settings.json` in tests (temp HOME); hook/settings writes are consent-gated with `--dry-run`.
- Follow the ENH-125 tool policy once Phase 170 ships (Read/Grep/Edit/Write/Task/TodoWrite).

## Acceptance Criteria
- [ ] `renderPolicyBlock` works for all 5 adapters and lists the 6 tools with adapter equivalents
- [ ] `classifyBashCommand` flags ≥ 12 forbidden patterns and passes ≥ 10 allowed commands (unit-tested)
- [ ] Mapping agrees with `getTodoCapability` and the adapter subagent field
