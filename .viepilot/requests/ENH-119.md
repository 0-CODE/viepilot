## Summary
vp-proposal has 4 types, all aimed outward (client, technical partner, investor, general). There is no type for presenting inside the company, and Step 3 picks the type from a static menu without asking who is in the room. Add an `internal-presentation` type with variants, ask about the audience first, then recommend a type for the user to confirm.

## Details

### Current behavior
- `PROPOSAL_TYPES` (lib/proposal-generator.cjs): project-proposal, tech-architecture, product-pitch, general.
- workflows/proposal.md Step 3: fixed 4-option menu; audience only enters later (persona keywords in Step 8b).
- review-personas.md: 20 personas skewed to external audiences.

### Desired improvement
1. **New type `internal-presentation` with variants** (one type, variant changes slide skeleton, tone and arc):
   - `team-intro` — introduce a project/product to colleagues
   - `leadership-report` — status/report up to leadership (decision or update)
   - `feature-demo` — internal demo of a feature/tool
   - `training` — training / onboarding
   - `all-hands` — company-wide update / town hall
   Each variant: base skeleton, diagram types, default voice suggestion, default duration, template mapping (stock pptx fallback allowed).
2. **Audience intake before type selection** (new step ahead of Step 3, AUQ on Claude Code, text fallback elsewhere):
   - Roles / departments present (multi-select, mark primary vs secondary): leadership, engineering, sales, operations, HR, clients, investors…
   - Decision maker: who approves, what they care about most (cost, risk, speed, technical soundness)
   - Knowledge level & size: technical depth, headcount, already familiar with the project or not
   - Format & goal: in-person / online / recorded; outcome wanted: approval, update, training, inspiration
3. **Recommend + confirm**: from the intake, recommend the best type (and variant) with a one-line reason plus 1–2 alternatives; user chooses. `--type` still overrides; intake answers are kept as `audienceProfile`.
4. **Audience profile reused downstream**: feeds voice suggestion (Step 3c), duration default, and persona selection (Step 8b) instead of free-text keywords only.
5. **Internal personas**: add internal persona cards beyond the fixed 20 (e.g. new hire, team lead, direct manager, peer from another department, busy executive skimming) with the same card format and rubric; audience mapping row for `internal-presentation` (per variant). #20 Humanity editor still always runs; quick mode stays 6–8.

### Why valuable
Internal decks are a large share of real presentations; tailoring by who is in the room avoids pitching investors-style decks to colleagues and makes persona review match the actual audience.

### Breaking changes
None intended: existing 4 types, `--type`, and persona ids 1–20 unchanged. New persona ids appended (21+).
