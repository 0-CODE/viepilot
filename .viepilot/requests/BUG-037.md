## Summary
The first live panel (6 personas + presenter, 3 rounds, 39 messages) worked end to end and was honest (presenter
answered "not in the material" 10/10), but surfaced these defects.

## Details
1. **Engine label not derived from how messages flowed.** The panelists were spawned as named teammates (mailbox),
   but they never messaged each other — the lead relayed every round through files/prompts. The report says
   `agent teams (direct messages)`. Expected: `engine` is computed — `teams` only when peer-to-peer messages exist in
   the transcript (from ≠ presenter/lead and delivered peer-to-peer), else `relay` — and the workflow says how to make
   teammates message each other directly (round 2: panelists `SendMessage` to each other, lead only opens/closes).
2. **`replyTo` ambiguity.** The panel prompt says `replyTo: [ids]`; panelists filled it with message ids (`q9-2`), the
   validator expects panelist ids → 3 false flags. Expected: accept panelist ids or message ids (resolve message id →
   its sender); prompt states which.
3. **`selectPanel` misses the strongest skeptics.** Run picked #3 (wouldAct true) as "most negative primary" and left
   out #9 / #12 (wouldAct false, most objections); the user had to swap them in. Expected: always seat the listener(s)
   with wouldAct=false and the most objections (questions+objections, not only unanswered), plus the lowest attention;
   "most negative primary" prefers wouldAct=false; tie-break by objections.
4. **`beforeAfter` only compares wouldAct.** #23 reported `changed: true` (now a conditional yes, signs off) but the
   table shows "unchanged". Expected: use the panelist's own `changed` + a `stance` field (e.g. "conditional yes"),
   and show conditions.
5. **Presenter over the word cap.** One answer > 80 words. Expected: presenter prompt reminds the cap per answer;
   validator flag kept (already works) and shown in the gate.
6. **Card text renders low** in LibreOffice renders (margin 0 top/bottom still sits below centre). Check the pptx
   anchor/insets (`anchor="ctr"`, `bIns/tIns`) the builder writes; fix in the guidance/builder pattern.
7. **`vp-tools proposal diff`** compares current vs current until `setCurrentVersion` runs. Expected: default to the
   latest version vs the previous one (or the current), with `--from/--to`.
8. **v2 backstage "Removed: none"** — sealed before the contentMap-array fix; next version (v3) regenerates it.
   Nothing to fix in code (fixed in 3.23.0); listed for the record.
