## Summary
1. Conversations about a proposal must stay inside the vp-proposal skill: the agent (Claude Code
   and others) must not lose the working context — after the deck is produced, during follow-up
   edits, after context compaction, or in a new session. Provide re-entry (resume) and automatic
   reminders instead of relying on the model's memory.
2. AskUserQuestion is mandatory at every gate and at every input and output of the workflow.
   Audit (2026-11-07, workflows/proposal.md after Phase 169.5): 14 of 21 steps have no
   AskUserQuestion — context_detection, purpose_consult, language_selection, quality_brief,
   manifest_generation, generate_docx_content, spoken_script, detect_visual_artifacts,
   template_resolution, generate_pptx, animation_hook, generate_docx, generate_md, google_slides_upload.

## Details

### A. Proposal session state (durable, not in the model's head)
- `docs/proposals/{slug}/session.json` written after EVERY step: `{ slug, status: in_progress|done,
  currentStep, completedSteps[], decisions: {type, variant, lang, voice, duration, audienceProfile,
  outlineApproved, contentMap, review, ...}, artifacts: {pptx, docx, md, script, backstage, ...},
  pendingGate, updatedAt }`. Decisions are recorded together with how they were confirmed (AUQ answer / flag / `--yes`).
- `vp-tools proposal status [--slug]` prints the active session(s); `vp-tools proposal resume` prints the step to continue from and the recorded decisions.
- `/vp-proposal --resume [slug]` re-enters the workflow at `currentStep` with all decisions restored — no re-asking of confirmed gates, no regenerating approved artifacts.

### B. Staying inside the skill during conversation
- New step **"Iterate" (after Confirm Output)**: any follow-up change request about an active
  proposal ("slide 3 is too long", "make it more humble", "add a slide about pricing") is routed
  through the workflow, not handled ad hoc: classify the change → which steps/gates it invalidates
  (outline, content map, manifest, script, animation, council) → re-run only those, with their gates.
- SKILL.md rule: while a proposal session is `in_progress` (or `done` with the user still discussing it), every user message about it MUST re-invoke `/vp-proposal --resume` (Claude Code: the Skill tool) before acting.
- **Claude Code hooks (consent-gated, reuse `vp-tools hooks install`)**:
  - `UserPromptSubmit`: when an active session exists in the project, inject a short context line —
    active slug, current step, pending gate, "re-enter with /vp-proposal --resume; every gate uses AskUserQuestion".
  - `SessionStart` (startup/resume/compact) or `PostCompact`: re-inject the session summary after compaction or in a new session.
  - Installed only with explicit consent (`--yes` or AUQ), dry-run supported, idempotent; never touches settings without consent.
- Other adapters: same rule in their skill/agent files + `vp-tools proposal status` at skill start (no hooks).

### C. AskUserQuestion at every gate — input and output
- Every `<step>` in workflows/proposal.md declares its gate(s):
  - **Input gate** — before the step consumes a decision or data (confirm source / choice; skip only when a flag or `--yes` provides it, and say so).
  - **Output gate** — after the step produces something the user would judge (outline, content map, manifest preview, script, animations, each file, council result, upload): accept / change / regenerate / stop.
  - Pure-compute steps (template resolution, pptx write) are merged into the adjacent output gate explicitly ("covered by gate: <step>"), never silent.
- Claude Code: AskUserQuestion is REQUIRED (preload via ToolSearch `select:AskUserQuestion`); plain text only if the tool errors. Other adapters: numbered text fallback with the same options.
- `--yes` (non-interactive) auto-accepts recommended options and records "auto-accepted" per gate in session.json and the .md summary; it never auto-accepts material-risk decisions from ENH-123.
- **Gate lint**: `tests/unit` (and `vp-tools proposal lint-gates`) parse the workflow and fail if any step lacks an `AskUserQuestion` gate or a valid "covered by gate" reference; the gate inventory table in the workflow must match the steps.
