## Summary
On Claude Code, vp-proposal MUST use the host's document skills — `anthropic-skills:pptx`,
`anthropic-skills:docx`, `anthropic-skills:xlsx` (and `anthropic-skills:pdf` where relevant) — for
creating, validating, rendering, reading and editing the proposal files, instead of relying only on
ViePilot's built-in generators. Explicit user opt-in to non-`vp-*` skills for this workflow
(exception to the BUG-004 namespace guard, scoped to vp-proposal).

## What the skills provide (inspected 2026-11-07, local copies under ~/.claude/skills/synced/…)
- **pptx**: creation with `pptxgenjs` (same library ViePilot uses — compatible), structured decks,
  theme application (`apply_theme.js`); editing via unzip → slide XML → zip, `add_slide.py`,
  `clean.py`; reading via `slide_text.py` (titles, text, tables, chart data, alt text, speaker notes);
  `thumbnail.py` grids; **File QA** `office/validate.py` (schema, relationships, content types,
  charts; notes that deleted animated shapes need their `<p:timing>` removed); **Visual QA**
  (LibreOffice via `office/soffice.py` → PDF → `pdftoppm` images; checklist: overflow, overlap,
  margins, contrast, alignment, split numbers, leftover placeholders); Content QA (placeholder grep).
- **docx**: creation with docx-js (same `docx` package ViePilot uses), verification, in-place XML
  editing, tracked changes (redlining with author), comments, accept changes.
- **xlsx**: creation/editing with openpyxl, mandatory formula recalculation (`recalc.py`),
  verification-safe formulas, financial-model conventions.
- **pdf**: reading/extracting, merging, creating PDFs.

## Details — where vp-proposal uses them (MANDATORY on Claude Code)
| Workflow point | Skill | Use |
|---|---|---|
| Step 6 Generate .pptx | pptx | follow the skill's pptxgenjs gotchas + structured-deck guidance; apply theme |
| Step 6b Animation | pptx | after ViePilot's `<p:timing>` post-process, run `validate.py`; fail-loud on any error |
| New: Deck QA gate (after 6b) | pptx | Content QA + File QA + Visual QA on every slide (render to images, inspect each — a subagent for fresh eyes); fix and re-render changed slides; results feed the council (C7) |
| Step 7 Generate .docx | docx | follow docx-js gotchas; verification step |
| Step 8b Persona council | docx | optional: council "Improve" items as Word comments on the .docx for the author |
| Budget / investment / work-plan tables (project-proposal, grant-proposal, progress-report, leadership-report) | xlsx | budget workbook with live formulas, recalculated and verified; figures in slides/docx come from it |
| ENH-126 import of hand edits | pptx `slide_text.py`, docx read | extract edited text + speaker notes back into the manifest (diff for confirmation) |
| Research types (ENH-120) | pdf | read reference PDFs supplied by the user; optional PDF handout export of the deck |
| Templates (`.viepilot/proposal-templates/*.pptx`) | pptx | template editing path + `validate.py --original` |

### Availability and enforcement
- At Step 1 (Initialize), detect the skills: Claude Code session skill list / Skill tool availability
  (names `anthropic-skills:pptx|docx|xlsx|pdf`). Record availability in session.json (ENH-124).
- Claude Code + skills available → using them is mandatory; each use is logged in provenance.json (ENH-126) as `skillsUsed`.
- Claude Code + a skill missing → AskUserQuestion: enable/install the skill and retry, or continue with ViePilot's built-in generator (explicit consent; QA steps that need the skill are marked "skipped — skill unavailable" in the summary and the council report, never silently passed).
- Other adapters (Cursor, Codex, Copilot, Antigravity) → built-in generators + whatever QA is possible locally; same "skipped" labelling.
- Dependencies of the skills (python-pptx, LibreOffice, Poppler, openpyxl) checked up front with clear install hints; missing LibreOffice no longer means a silent skip.

### Consistency rules
- ViePilot remains the source of truth for the manifest, script, animation rules, validators
  (`validatePptxAnimations`, `detectProcessLeak`, `detectDevNotes`) and gates; the document skills
  are the execution and QA layer. Both sets of checks must pass.
- The pptx skill's guidance to prefer a slide-deck artifact type does not apply: vp-proposal's
  deliverable is an explicit .pptx file.
- Policy ENH-125 still applies (Read/Edit/Write/Task/TodoWrite); the skills' own scripts are run via Bash as programs.
