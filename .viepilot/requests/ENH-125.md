# ENH-125: Tool-use policy for all ViePilot skills and agents — Read / Grep / Edit / Write / Task / TodoWrite, not sed or ad-hoc scripts

## Meta

- **Reporter**: User
- **Assignee**: AI
- **Branch**: from-3.12.2

## Summary
Every ViePilot skill (and every agent it spawns) must always use the host's dedicated file tools:
Read to read files, Grep/Glob to search, Edit to change files, Write to create files. Agents today
often edit with `sed -i`, Python/Node one-off scripts or heredoc redirects, and read with
`cat`/`head`/`sed -n` — harder to review, bypasses the host's diff/permission UI, and breaks easily
(wrong anchors, silent no-ops, encoding issues).

## Audit (2026-11-07)
- 22 SKILL.md files list the tools in their adapter block ("Use Claude Code tools: Bash, Read, Edit + Write, Grep…") but none states a rule that file reads/searches/edits MUST use the dedicated tools.
- All 14 Claude Code agents (`agents/claude-code/*.md`) have `Bash` in `tools:`; none has a tool-use policy; read-only agents (file-scanner, vp-phase-planner, vp-quality-gate) do not need to edit through Bash at all.
- Orchestrator dispatch prompts (vp-auto → vp-task-executor) carry no tool-use rule; executors in phases 165–169 frequently edited via Python/sed.

## Details

### Policy (single source, injected everywhere)
- New `templates/tool-policy.md` (or a `<tool_policy>` block generated into each SKILL.md), adapter-mapped:
  | Need | Claude Code | Cursor | Codex | Copilot | Antigravity |
  |---|---|---|---|---|---|
  | read a file | Read | read_file | (shell read allowed — no dedicated tool) | read/readfile | file_read |
  | search | Grep / Glob | grep_search / file_search | shell `rg` | code_search | shell |
  | edit a file | Edit | edit_file | apply_patch | edit/editFiles | file_write |
  | create a file | Write | edit_file | apply_patch | editFiles | file_write |
  | run programs (tests, git, node, vp-tools) | Bash | run_terminal_cmd | container.exec | runCommands | shell |
  | plan & track work (task list) | TodoWrite — or TaskCreate / TaskUpdate / TaskList when the session exposes them (ENH-118 `getTodoCapability`) | todo_write (unverified → `## Todo` checklist fallback) | update_plan | todos (unverified → checklist fallback) | write_todos |
  | delegate a sub-task to a subagent | Task (Agent tool, `subagent_type`) | none callable (`/multitask` is a user command) → do it inline | subagent (single-level) | subagent (single-level; no askQuestions inside) | none → inline |
- Rules (user-required tool set, 2026-11-07): **Read, Grep/Glob, Edit, Write, Task, TodoWrite**.
  - **Write** creates new files or fully replaces a file that was Read first; Edit for partial changes.
  - **TodoWrite** (or the TaskCreate/TaskUpdate/TaskList family) MUST hold the working task list for any multi-step skill run (evolve, auto, proposal, …) and be kept in sync — one item `in_progress` at a time, marked done immediately; this is the native mirror required by ENH-118, not an optional extra.
  - **Task** (Agent tool) MUST be used for delegated work defined by the workflows (vp-task-executor, tracker-agent, changelog-agent, persona reviewers, research, file scans) instead of doing that work inline or via shell scripts; prompts passed to subagents carry this same policy.
  - MUST NOT modify files via `sed -i`, `perl -pi`, `awk … > file`, Python/Node scripts that write files, `cat <<EOF > file`, `tee`, or `>`/`>>` redirects into tracked files; MUST NOT read files with `cat`/`head`/`tail`/`sed -n` when a read tool exists; Bash is for executing programs and git only.
- Allowed exceptions (explicit): files produced by ViePilot's own lib/CLI (`vp-tools …`, pptx/docx generators, `todo sync`); bulk identical edits across ≥ 5 files go through `doc-sync-agent` (which itself uses Edit); adapters without a dedicated tool (Codex read/search) use the shell.
- Where the host provides it, the session/harness system instruction still wins; the skill states the policy and the agent reports when it cannot follow it.

### Where it is applied
- Every `skills/vp-*/SKILL.md` gets the policy block (all adapters' sections).
- Every `workflows/*.md` header references it; workflow code blocks that show file edits are rewritten as tool instructions (keep bash only for commands).
- Every `agents/claude-code/*.md` gets the policy; read-only agents lose `Bash` where not required, or keep it with "commands only".
- vp-auto dispatch template (autonomous.md) includes the policy in every executor/tracker/changelog prompt.

### Enforcement
- **Lint test**: fails if any SKILL.md or agent file lacks the policy block, or if skills/workflows/agents instruct editing via sed/awk/perl/python/heredoc redirects.
- **Claude Code PreToolUse hook (consent-gated, via `vp-tools hooks install`)**: inspects Bash commands; on edit/read patterns (`sed -i`, `perl -pi`, `python… open(…,'w')`, `> path`, `tee`, `cat file`, `head file`) returns a warning ("use Edit/Read") in `warn` mode or blocks in `block` mode (`vp-tools config set tools.policy warn|block|off`, default warn). Dry-run, idempotent, temp-HOME tests; never touches the real settings without consent.
- **Orchestrator review**: vp-quality-gate checks executor reports/transcripts summary for policy violations and lists them.

## Discussion
User (2026-11-07): all ViePilot skills should always require Edit to modify files, Read to read and
Grep to search; agents very often use sed or Python to edit instead of the agent tools.
Follow-up (same day): also add the Write, Task and TodoWrite tools to the policy.
Note: in the session that logged this, the harness itself (bypass-permissions mode) instructed the
orchestrator to prefer Bash, which is why the orchestrator also edited via Python/sed — the policy
must state that a host/system instruction takes precedence and must be reported, not silently followed.
