## Summary
Let `/vp-evolve` run its exploration in Claude Code Plan Mode (read-only) and present the phase/task plan through
`ExitPlanMode` for one native approval before any plan file is written.

## Proposal
- `--plan-mode` flag; suggested automatically (AskUserQuestion) when complexity is L/XL or the request is vague.
- Flow: `EnterPlanMode` → read code, architecture check, research → draft phase + tasks → `ExitPlanMode` with the draft
  → on approval write ROADMAP / SPEC / tasks **verbatim** from the approved plan (doc-first, survives compaction).
- `ExitPlanMode` replaces the "confirm plan" AskUserQuestion — no duplicate gate.
- Hosts without Plan Mode (Codex, Copilot, Antigravity; Cursor Agent mode) and subagents: current AUQ flow.
- Not the default for `/vp-auto` tasks; optional per task for high-risk tasks only (`--plan-mode` on vp-auto task).

## Expected effect (not measured)
Better plans and less rework for large / unclear requests; one consolidated approval; safe read-only exploration.
Likely slightly more tokens, not fewer.

## Acceptance Criteria
- [x] `--plan-mode` documented in vp-evolve SKILL + workflow, auto-suggested for L/XL
- [x] approved plan written verbatim into SPEC/tasks; no duplicate confirm gate
- [x] fallback documented per adapter; tests for the workflow text
