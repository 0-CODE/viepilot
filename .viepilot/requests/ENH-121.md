## Summary
After all proposal steps are done, offer a simulation mode: put the personas into a simulated hall
and "present" the whole deck with its spoken script along a real timeline (slide by slide, line by
line, click by click). Personas listen, react and drift, and the run produces evaluations, what to
improve, when each persona stopped taking it in, a retention curve, keyword and criteria
effectiveness, plus additional charts — viewable in a self-contained HTML report with a 3D hall
that replays what happened over the timeline. Re-runnable on an existing proposal after edits.

Difference from the Persona Review Council (ENH-117c): the council reads the deck as a document; the
hall listens over time, so it can say *when* and *why* attention was lost.

## Details

### Trigger
- At the end of the proposal flow, AUQ asks whether to run the Rehearsal Hall (default recommended yes).
- Re-run anytime: `/vp-proposal --simulate <proposal output dir>` (optionally `--duration 5|15|30`, `--hall all`, `--add/--remove <ids>`).
- Each run is stored as `simulation/run-{n}/` next to the proposal so runs can be compared.

### Audience in the hall
- Default: every persona relevant to the proposal type + audienceProfile (~12–16), #20 always present.
- `--hall all` puts the whole library (30) in the room; add/remove individual personas.
- Primary-audience / decision-maker personas are weighted (same ×2 rule as the council).

### Simulation model
1. **Timeline builder (deterministic, code)**: from the slide manifest, spoken script (chosen duration
   version) and `[click]` cues → segments `{slide, cue, line, tStart, tEnd}` using a speaking rate
   per language (configurable wpm); flags overruns vs planned slide time.
2. **Slide load metrics (deterministic, code)**: words on slide, numbers, jargon/acronyms, bullets,
   animation builds, text density → cognitive-load score per slide.
3. **Persona listeners (LLM, one independent subagent per persona)**: receive their card, the
   audience context and the timeline; emit per segment `{attention 0–100, comprehension 0–100,
   emotion −2..+2, funnelStage aware|understand|agree|act, question?, objection?}`, a `tuneOut`
   `{segment, t, reason}` (or null), `regainedAt?`, recalled keywords/messages after 24h, final
   verdict + quote-backed evaluation. Strict JSON; every negative claim cites the segment and line.
4. **Aggregator (deterministic, code)** computes every chart's data from the listener outputs.

### Outputs (the 5 asked for)
- Persona evaluations: verdict (would approve/act?), scores on the existing rubric (H1–H2, C1–C8, R1–R3 for research), quotes.
- Improvements: prioritized by impact (weighted attention loss × audience weight), each tied to slide + line + suggested fix.
- Tune-out moments: per persona, the exact slide/cue/second they stopped taking it in, with reason; regain points.
- Retention curve: % of hall still attentive over time (all, primary-weighted), slide boundaries marked.
- Keyword & criteria effectiveness: per intended key message/keyword — times said, where, recall rate after 24h, association (positive/negative), plus rubric criteria scores by persona group.

### Additional charts (user-approved — all four groups)
- **Attention & cognition**: attention heatmap persona × slide; cognitive load per slide; confusion spikes (comprehension drops) with their cause (jargon/numbers/density).
- **Emotion & persuasion**: emotion arc vs the intended narrative arc (context → conflict → turning point → solution → proof → invitation); persuasion funnel aware → understand → agree → act per persona/group.
- **Questions & pacing**: question/objection map by slide, unanswered objections; pacing — planned vs simulated time per slide, words per minute, overrun points.
- **Recall & comparison**: what is remembered after 24h vs the intended key messages; decision-maker-weighted retention vs the rest of the hall; run-over-run deltas (retention, tune-outs, scores) between simulation runs.

### 3D hall replay (user-added)
- Self-contained HTML includes a 3D hall: stage with the current slide, seats for each persona
  (avatar label + role), seat colour = attention at time t, icons for question/objection, dimmed
  seat after tune-out, highlight for decision makers.
- Timeline scrubber + play/pause/speed; the current script line and slide title are shown in sync;
  clicking a seat shows that persona's live state and their evaluation.
- Rendering with three.js embedded in the HTML so it opens offline (no CDN dependency); automatic
  fallback to a 2D top-down hall (SVG) when WebGL is unavailable.

### Report format (user-approved)
- `simulation/run-{n}/report.html` — self-contained, inline SVG charts + 3D hall, light/dark, labelled "AI simulation — not real audience data".
- `simulation/run-{n}/summary.md` — verdicts, top improvements, tune-out table, key numbers.
- `simulation/run-{n}/data.json` — timeline, listener states, aggregates (input for comparison runs).
