- **Assignee**: AI

## Summary
Today every listener is a one-shot subagent that hears the talk alone and returns JSON; nobody talks to anybody.
The user wants a real exchange: personas discuss with each other, challenge each other, and question a **presenter
agent** directly, with back-and-forth messages.

## Research (Claude Code, 2026-11 docs)
- **Subagents** (Agent/Task): run independently; the orchestrator can continue a finished subagent with
  `SendMessage` (context kept). Peer-to-peer messages between running subagents are not a documented pattern.
- **Agent teams** (experimental, `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`): teammates message each other directly
  (mailbox, automatic delivery), shared task list, idle notifications; hooks `TeammateIdle`, `TaskCompleted`,
  `TaskCreated` (exit 2 = keep working / block). Docs recommend 3–5 teammates; cost scales linearly with teammates;
  one team per session, no nesting; known limits (resume, task-status lag, slow shutdown). No turn-order primitive —
  rounds must be driven by the lead.
- **Other hosts** (Cursor, Codex, Copilot, Antigravity): no official agent-to-agent messaging.

## Proposal (recommended design)
**Keep both, in two phases — do not turn all 16 listeners into teammates.**

1. **Phase A — Listening stays independent (subagents, as now).** Independent first impressions are the point of a
   rehearsal: if listeners talk while listening, they herd (copy the loudest opinion) and the retention / tune-out
   data stops meaning anything. Cheap, parallel, verifiable (BUG-036 grounding).
2. **Phase B — Panel Q&A with real messages (new).** After listening, a small panel debates and questions the speaker:
   - **Presenter agent** — plays the speaker; answers **only** from the deck, notes, backstage and Content Map; must
     cite the slide / source of each answer; when the material has no answer it says so ("chưa có — ghi lại"), never
     invents. Every unanswered question becomes a deck gap.
   - **Panel: 4–6 personas** chosen from Phase A: the most negative primary persona, the lowest-retention persona,
     the persona with the most unanswered objections, #20 Humanity editor, plus one decision-maker. Moderator = the
     orchestrator (lead).
   - **Rounds (max 3, enforced by the lead):** R1 each panelist asks the presenter its sharpest question (from its
     Phase A objections); presenter answers with citations. R2 panelists reply to *each other* — agree, push back,
     add evidence ("bàn vô bàn ra"), each message must reference another panelist's point. R3 final position: changed
     mind or not, and why. Hard caps: max messages per agent, max words per message.
   - **Output:** a transcript (who → whom, round, cited slide/source), per persona *before vs after* (attention to the
     ask, wouldAct) to show what the Q&A changed, the questions the presenter could not answer (→ backstage / deck
     fixes), and a "debate" section + chat-style replay in report.html.
3. **Transport — one protocol, two engines.**
   - **Claude Code with agent teams enabled:** panel + presenter as teammates; messages are real `SendMessage`
     exchanges; `TeammateIdle` hook keeps a panelist working until its round message is posted; the lead advances
     rounds. Requires opt-in (experimental env var, consent, `--panel teams`).
   - **Default / other hosts:** the orchestrator relays messages between continued subagents (Claude Code
     `SendMessage` to each panel subagent per round) or runs the rounds sequentially in-thread — same message schema,
     same caps, labelled "relayed".
4. **Honesty rules carry over:** every message is an AI simulation; quotes must be selective; presenter answers
   without a citation are flagged; the panel is shown as a model discussion, not audience data.

## Why not all 16 as teammates
Cost (~17 context windows talking for several rounds), docs recommend 3–5 teammates, experimental limits, and herding
destroys the independent listening data. A small panel after independent listening gives the debate the user wants
and keeps the measurements meaningful.
