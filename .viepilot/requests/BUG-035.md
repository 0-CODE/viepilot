## Summary
A full real run of `/vp-proposal` (internal-presentation / team-intro, vi, Humble, 15 min, council quick + #31,
Rehearsal Hall) on installed 3.22.1 completed, but surfaced the defects below. One was hotfixed in-chat
(G0); the rest are open. Group G8 is an agent-behaviour defect the user caught: the run ended with a question to
the user written as plain text instead of AskUserQuestion, breaking the ENH-124 rule "every gate, every input and
output".

## Details (by group)

### G0 — Rehearsal Hall parser (FIXED, commit d6132ad, not yet installed)
- `parseListener` started `prevAttention` at 100, so a listener whose first state was below 80 counted as an
  uncited drop; the held value then re-dropped every later segment (73 of 12 listeners' reactions discarded, slide
  1–2 attention inflated 88→75 / 75→69). Fixed: first state = baseline; held drop counted once. 3 regression tests.

### G1 — Audience selection (hall + council)
- `selectHall` fills to 12 from the generic full set → seats Investor #5, CFO #2, Procurement #6, Existing customer #8
  in an internal engineering team-intro. Internal types must fill from internal/role-mapped personas first and never
  seat external-only personas (investor, procurement, customer) unless the audience includes them.
- Role mapping `product → [14]` (Marketing/Brand); council quick also picks Marketing #14 and Designer #13 for an
  engineering team-intro.
- `manifest.audienceProfile` is never written (only a free-text `manifest.audience`), so `selectHall`
  /`selectPersonas` fed from the manifest get no profile → `primary: []`.

### G2 — Session / store consistency
- `setCurrentVersion` updates `proposal.json` but `session.currentVersion` stays `null`.
- `recordGate` keys by step only → the `output` gate overwrites the `input` gate of the same step
  (persona_review_council, rehearsal_hall). Store both (`gates[step].input|output`) with migration.
- `versionPaths().outline` is `{slug}-outline.md` but holds JSON (workflow says outline.json).
- `versionPaths().scriptDocx` is listed but no step produces it.
- In-run regeneration of an unaccepted draft conflicts with `wx` immutability (had to delete drafts by hand);
  versions should be sealed at Confirm Output, drafts rewritable before that.
- Provenance is written at Confirm Output, then the Rehearsal Hall adds files → provenance must be refreshed (or
  simulation runs hashed separately) automatically.

### G3 — Purpose / audience hints
- "đồng nghiệp kỹ thuật" not detected as an engineering audience; no `qa` / `tech-lead` roles; "dùng thử" /
  adopt / pilot not a goal.

### G4 — Source inventory / Content Map
- False positives: `scripts/`, `tests/` classified as evidence; `agents/changelog-agent.md` as process-log;
  `templates/tests` as architecture. Misses `docs/user/*`. Stale README facts (3.8.0, 2210 tests) offered as FIT
  without a staleness flag.

### G5 — Script / timing
- `planDuration` / timeline do not model fixed segments (live demo, Q&A): 15-min plan, 7:39 of spoken notes,
  every slide flagged underrun. Need demo/Q&A blocks in the plan and in the hall timeline.
- `buildScriptMarkdown` "Audience:" header empty (needs the profile/audience); Q&A section empty unless
  `manifest.qa` exists — should fall back to council questions.

### G6 — Curation / backstage
- `detectDevNotes` false positives: "đang làm" in "quên mình đang làm gì", "chưa có" in honest statements; no
  "keep — false positive" action; quotes cover the whole note instead of the line.
- `buildBackstage`: duplicates Q&A items under Open items; English headings in a vi deck; "Removed: (none)" ignores
  Content Map DROP items; "Reframed on the slides" can claim a reframe that is not on the slide.
- Cross-file consistency is not checked (slide said install guide is in the channel *before* the session, notes
  said *after*).
- Placeholders like `[điền tên + kênh trước buổi]` reach the rendered deck; Confirm Output should block (or force an
  explicit accept) while placeholders remain.

### G7 — Animation / packaging
- `pptx-animate` 'auto' counts the slide-number (and date/footer) placeholders as builds.
- `validatePptxAnimations` does not compare build count with `[click]` cues in the notes.
- pptxgenjs/JSZip output keeps ZIP directory entries (remove them, as the docx/pptx skills require).
- `apply_theme.js` needs `NODE_PATH=$HOME/.claude/viepilot/node_modules` — workflow must set it.

### G8 — Questions to the user without AskUserQuestion (agent behaviour)
- Observed: after the run closed, the final message ended with "Bạn có muốn mình gom các lỗi này thành request… ?"
  as plain text. The user had to answer by typing a new command.
- Cause: workflows mandate AUQ only at named gates; the closing summary / "what next" and ad-hoc questions are not
  covered, and nothing checks the final message.
- Expected: every question to the user on Claude Code goes through AskUserQuestion — including the end-of-run
  next step and any question outside a named gate. Fix in the shared skill block (all vp-* skills, like the tool
  policy block), in `workflows/proposal.md` (explicit closing "Next step" AUQ after finishSession), and optionally an
  opt-in Stop hook (`hooks install --auq-check`) that warns when the last assistant message ends with a question and
  no AskUserQuestion call was made in that turn.

### G9 — Other
- Persona-review prompt template contains `{persona_card}` in its own text → card duplicated.
- "AI simulation — not real audience data" label appears once in report.html; spec says every page/section.
- `npx viepilot install` installs the npm release, not the branch build (presenter instructions must say so).
