# BUG-033: Installer never installs or updates runtime dependencies of the installed copy

## Summary
`viepilot install` copies `lib/`, `bin/`, `templates/`, `workflows/`, `package.json` into `~/.claude/viepilot`
(and the other adapters' dirs) but never runs a dependency install there. The installed copy keeps whatever
`node_modules` happened to exist before (311 packages from an old install, including dev dependencies).

## Impact
- Dependencies added after that old install are missing in the installed copy: `three` (ENH-121, 3D hall replay —
  falls back to 2D), and any future runtime dependency. `jszip` (3.15) and `pptxgenjs` / `docx` only work because an old
  `node_modules` happens to contain them; a fresh machine has none of them.
- Version drift: installed `node_modules` versions do not follow `package-lock.json`.

## Expected
After copying, the installer installs production dependencies in each installed ViePilot dir
(`npm ci --omit=dev` when the lock file is present, else `npm install --omit=dev`), with a clear message, a
`--skip-deps` flag for offline use, a dry-run line in the plan, and a non-fatal warning (with the manual command) when
the install fails. Features with optional heavy dependencies (three) keep their fallbacks.

## Acceptance Criteria
- [ ] Install plan has a `deps_install` step per installed dir (shown in `--dry-run`)
- [ ] Production-only, lock-file based; `--skip-deps` honoured; failure is a warning with the manual command
- [ ] Unit tests with a temp HOME and a stubbed npm runner (no network in tests)
- [ ] Docs: install guide mentions the step and `--skip-deps`
